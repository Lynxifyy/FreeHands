FreeHands: a mobile agent stack

Phases 1–3 of a phone-side agent: a native capture bridge, a bounded agent loop, and an on-device inference engine — all inside the 150 ms latency budget.

What this PR is

Three phases, each independently testable, all async, all under one latency budget. Phase 1 and Phase 2 landed earlier in this branch; Phase 3 is the substance of the latest commits.

Phase 3: the gap that was closed

Before

Kotlin already declared the interface it wanted:

// InferenceAdapters.kt
private external fun nativeOpen(path: String): Long
private external fun nativeGenerate(h: Long, p: String, t: Int): String
private external fun nativeClose(handle: Long)
// System.loadLibrary("litertlm")

No liblitertlm existed. loadLibrary threw UnsatisfiedLinkError, isAvailable stayed false, and every request silently fell through to the cloud. The "offline-first" promise only held while the network held.

After

A real engine, host-testable, plus the JNI bridge:

cpp/src/  memory_pool.cpp  kernel_backend.cpp
          tokenizer.cpp    quantization.cpp
          kv_cache.cpp     model.cpp
          litert_engine.cpp
          litert_engine_jni.cpp   <-- liblitertlm

The engine has no Android headers. It builds and runs on the host, so the whole path — tokenize → prefill → decode — is covered by tests, not only by a device run.

Engine internals

UnitWhy it exists
MemoryPoolOne reserved block for activations, reset per step. A fresh allocation on Android can trigger a stop-the-world GC mid-stream, which surfaces as a dropped frame.
KernelBackendThe matmul seam. CpuKernelBackend is the portable reference; a LiteRT-LM delegate implements the same two calls, so a GPU path touches no other file.
TokenizerBPE over the model's piece table, greedy longest match with a byte fallback, so encoding never fails on unknown input.
QuantizedTensor4-bit and 8-bit affine weights, per-block scales, decoded a row at a time during the matmul — a 4-bit checkpoint keeps its memory saving while it runs.
KVCachePaged keys and values with a ring policy. Pages never move once written, so per-token cost stays flat instead of rising with sequence length.
ModelLoaderReads a .litertlm container. A wrong signature or version is refused with a reason rather than partially loaded, because a half-loaded model produces plausible-looking garbage.
LiteRTEngineCausal attention with a real softmax, layer norm, SiLU MLP. Greedy sampling by default so the agent's structured output is reproducible. Per-token streaming, cancellation, thermal cutoff, prefill/decode stats.

The 150 ms budget, enforced not asserted

The budget is a runtime object, not a comment. LatencyBudget owns the target and the per-stage samples; the capture bridge takes it as a constructor argument and the queue drops the oldest frame when it overflows, so latency degrades by dropping frames rather than by growing a backlog.

LatencyBudget.DEFAULT_BUDGET_MS = 150L
ScrcpyBridge(latencyBudgetMs = LatencyBudget.DEFAULT_BUDGET_MS, ...)
  -> nativeCreate(width, height, fps, bitrateKbps, latencyBudgetMs, queueCapacity)

AdaptiveQuality lowers resolution and bitrate when the measured end-to-end time crosses the budget, and restores it when the headroom returns.

Async by construction

  • Capture runs on its own native thread; frames reach Kotlin through a registered sink, never a blocking call.
  • The agent loop runs on a dedicated freehands-agent thread; the service publishes progress through AgentRuntime, a StateFlow, so the Compose layer observes instead of polls.
  • Generation streams token by token through a callback, so the UI paints as text arrives rather than after the last token.
  • Health checks and the feed server are separate servers on their own threads; neither blocks the loop.

Correctness work found by the tests

Six defects, each caught by a test that failed first:

  1. MemoryPool aligned only the offset, so the first block was misaligned whenever the backing array was.
  2. A constant quantization block collapsed to zero: the scale was left at 1.0 instead of derived from the block's own value.
  3. KVCache stored one buffer for both keys and values.
  4. The tokenizer test literals hit the classic C++ hex-escape trap — "\xE2\x96\x81abc" is not the marker followed by abc. Fixed with a named constant, and the tokenizer now guards against double-marking.
  5. Resource leak: the service never closed the native engine. Stopping the stack left the model allocated for the life of the process, so a restart loaded a second copy.
  6. Use-after-free: close() could free the engine while generate() was inside it — the stop path and the agent thread are different threads, and a raw pointer must be dereferenced before it can be checked. Sessions now live in a registry keyed by the handle; each call takes a shared reference under the lock, so the engine is freed by whichever call is last, which is never one still running.

Compatibility

Every added Kotlin surface is additive. InferenceResult gained optional token fields defaulting to null; LocalInference gained a close() with a no-op default, so existing implementations compile unchanged. A build without the native library behaves exactly as before: the route is simply unavailable and the agent uses the cloud.

Telemetry note: InferenceResult carries token counts as nullable on purpose. A route that can measure them implements InferenceTelemetrySource; one that cannot leaves them null so the metrics fall back to an estimate, rather than reporting an invented number as if it were measured.
